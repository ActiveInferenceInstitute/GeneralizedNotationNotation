### N-1 — Fold `resolve_step_output_dir` fallback semantics into the helper (W2-J1 residual)
- **LANDED 2026-09-15** (`d79c62756`; TO-DO.md W2-J1 row, CHANGELOG
  2026-09-15 wave entry): one explicit fallback policy in the helper
  (caller-supplied directory on standalone use); both wrappers are thin
  delegates (`framework_common.resolve_execution_dir`,
  `gui/runner.resolve_output_root`) and both divergent
  `except ImportError` blocks are deleted; call-site parity pinned over
  `output/`, `output/7_export_output/`, and arbitrary subdirs.
  `tests/pipeline tests/analysis -q` → 967 passed; GUI composability →
  21 passed. HEAD-verified: no private fallback remains in either
  wrapper.
- **Severity**: major | **Category**: architecture
- **Motivation**: the shared helper `gnn.pipeline.config.resolve_step_output_dir`
  exists and all three historical call sites route through it, but the two
  wrapper helpers keep divergent `except ImportError` fallbacks:
  `src/gnn/analysis/framework_common.py:130-131` returns
  `output_dir.parent / "12_execute_output"` while
  `src/gnn/gui/runner.py:29-30` returns `output_dir` unchanged — two
  different recovery semantics for the same failure mode, silently divergent
  between analysis and GUI standalone use. The third site's migration is
  confirmed (`src/gnn/export/processor.py:585-588`).
- **Scope**: give the helper one explicit fallback policy (document the
  standalone behavior; prefer returning the caller-supplied directory or the
  registered step dir — pick one, do not keep both); repoint both wrappers to
  it (or inline them) and delete the divergent `except ImportError` blocks.
- **Acceptance probe**: unit tests pin identical resolved paths through every
  call site for `output/`, `output/7_export_output/`, and arbitrary subdirs;
  `uv run --extra dev python -m pytest tests/pipeline tests/analysis -q` green.
- **Effort**: S/M | **Order**: standalone; pairs naturally with a config seam PR.

# output/ Tracking Boundary

Decision (2026-09-10, wave SC-9): `output/` follows a **curated-vs-volatile**
boundary instead of the former "track everything" policy. The single source of
truth for the ignore rules is `.gitignore` (section *GENERATED ARTIFACT TREES*).

## Boundary

| Path | Class | Evidence |
|---|---|---|
| `output/manuscript/` | CURATED | Manuscript gates read the sections/config (tests/test_manuscript_* suite) |
| `output/pdf/` | CURATED | `tests/test_manuscript_latex_log.py` pins `.log`/`.aux`/`.bbl`/`.toc` evidence of the shipped PDF |
| `output/figures/` | CURATED | `figure_registry.json` + the 6 PNGs it references; figure-freshness gate reads the registry |
| `output/data/` | CURATED | `manuscript_variables.json` is the manuscript variable gate input (TokenGates regenerates it; stays tracked) |
| `output/slides/` | TRACKED — FLAGGED | Beamer bundles mirroring `output/manuscript/` section slugs; no gate/test reads them, but no in-repo writer was found either (repo-wide grep), so they fail the "regenerable" test and were left tracked per the ambiguity rule |
| `output/web/` | TRACKED — FLAGGED | Manuscript HTML site; same situation as `output/slides/` (no reader, no in-repo writer) |
| `output/reports/` | TRACKED — FLAGGED | `manuscript_composition.json`; same situation as `output/slides/` |
| `output/[0-9]*_*_output/` | VOLATILE | Per-step pipeline outputs (e.g. `3_gnn_output`, `8_visualization_output`, `11_render_output`); regenerated by every run of `src/main.py` |
| `output/00_pipeline_summary/` | VOLATILE | Written by the pipeline orchestrator each run (`pipeline_execution_summary.json`, `.history/`) |
| `output/00_pipeline_logs/` | VOLATILE | Structured run logs (`pipeline.jsonl`) written every run |
| `output/PIPELINE_REPORT.md` | VOLATILE | Written by `_write_final_pipeline_report` (`src/gnn/main.py`) and `report/__init__.py` each run |
| `output/semantic_fidelity/` | VOLATILE | Ledger regenerated by `scripts/run_semantic_fidelity_gate.py` |
| `output/cross_framework/` | VOLATILE | Ledger regenerated by `scripts/run_cross_framework_reliability.py` |
| `output/model_family_acceptance/` | VOLATILE | Ledger regenerated by `scripts/run_model_family_acceptance.py` |
| `out/` | VOLATILE | Historical stray run outputs (7 files untracked from the index) |

| `output/api_contract_test/`, `output/job_contract_test/` | VOLATILE | Contract-test scratch written by `tests/api/test_api_endpoints.py` (:179, :234) |

## Rationale

Volatile step outputs were 6.6k+ tracked files that tests and pipeline runs
regenerate, dirtying `git status` after every full-suite run. Only artifacts
that published gates read as evidence need to be in git; everything else is
reproducible by running the pipeline.

## Regenerating volatile outputs

- Step outputs, summary, logs, `PIPELINE_REPORT.md`: run the pipeline
  (`uv run src/main.py` with any input config under `input/gnn_files/`).
- `semantic_fidelity/`, `cross_framework/`, `model_family_acceptance/`:
  run the corresponding `scripts/run_*` script.

## Re-adding a curated artifact

If a new published artifact must join the curated set:

1. Add an explicit non-ignored comment line to the CURATED list in
   `.gitignore` (patterns are listed as documentation; the rules only ignore
   the volatile paths, so nothing to negate unless a pattern collides — use a
   `!` negation in that case).
2. `git add <path>` and document the reader (which gate/test consumes it) in
   the table above.
3. Do not place curated artifacts under a path matched by a volatile pattern
   (`output/[0-9]*_*_output/`, `out/`, …); if unavoidable, negate explicitly.
